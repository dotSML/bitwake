# Competitor analysis

This is a clean-room product comparison, not an implementation reference. The review was limited to VueTorrent's public README, feature claims, and published desktop/mobile screenshots. No VueTorrent source code, component hierarchy, API client, state management, styles, visual tokens, translations, icons, or other assets were used. Nothing from VueTorrent is copied into this project.

## Sources and scope

- [VueTorrent README and published feature inventory](https://github.com/VueTorrent/VueTorrent/blob/master/README.md)
- [VueTorrent repository landing page](https://github.com/VueTorrent/VueTorrent)
- [qBittorrent 5.2.3 stock WebUI](https://github.com/qbittorrent/qBittorrent/tree/release-5.2.3/src/webui/www)
- [qBittorrent WebUI API documentation for 5.0+](<https://github.com/qbittorrent/qBittorrent/wiki/WebUI-API-(qBittorrent-5.0)>)

The VueTorrent README documents torrent operations, selective file download, details, search, keyboard shortcuts, session statistics, transfer graphs, a PWA-capable mobile interface, configurable torrent properties, mocked development data, and an optional settings backend. Its published screenshots show a card-led torrent workspace, persistent labels for individual values, prominent colored state/category/tag chips, a statistics-heavy sidebar, and a large mobile navigation drawer. Those broad observations are sufficient to establish the product trade-offs below; they are not a license to reproduce the design.

Rows marked **Guardrail** are architectural constraints from this project's brief, not claims about VueTorrent internals.

## Decision table

| Observed pattern                                                        | Adopt, reject, or reinterpret | Reason                                                                                                               | Our implementation                                                                                                                              |
| ----------------------------------------------------------------------- | ----------------------------- | -------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| Broad qBittorrent feature coverage                                      | **Adopt**                     | A replacement WebUI must preserve power-user workflows, not reduce qBittorrent to a download list.                   | Track stock 5.2.3 coverage in `feature-parity.md`; capability-gate version-dependent behavior.                                                  |
| Direct operation over qBittorrent's Web API                             | **Adopt**                     | Same-origin API access is the native Alternative WebUI model and keeps deployment simple.                            | Typed, namespace-based `/api/v2` client using browser-managed authentication cookies.                                                           |
| Responsive intent                                                       | **Adopt**                     | qBittorrent is commonly managed from phones and tablets as well as desktops.                                         | Three purposeful compositions: dense desktop workspace, adaptive tablet layout, dedicated mobile routes and sheets.                             |
| PWA installation                                                        | **Adopt**                     | Installation and standalone display improve frequent mobile use.                                                     | Manifest and static-asset-only service worker; `/api/**` and authentication responses remain network-only.                                      |
| Keyboard shortcuts                                                      | **Adopt**                     | High-frequency selection and filtering benefit from keyboard efficiency.                                             | Context-scoped `Ctrl/Cmd+A`, `Ctrl/Cmd+F`, Escape, Delete confirmation, arrow navigation, and range selection.                                  |
| Drag-and-drop torrent addition                                          | **Adopt**                     | It is a natural desktop entry point and complements file and URL inputs.                                             | One add flow for dropped files, file selection, magnets, torrent URLs, search results, and RSS articles.                                        |
| Integrated torrent search                                               | **Adopt**                     | Search is part of qBittorrent's stock WebUI and official API surface.                                                | Lazy-loaded search jobs, filters, plugin management, result inspection, and add/download actions.                                               |
| RSS reader and downloader                                               | **Adopt**                     | RSS feeds and rules are first-class stock WebUI workflows.                                                           | Lazy-loaded feed tree, sanitized article detail, read state, refresh actions, and grouped rule editor.                                          |
| Torrent Creator                                                         | **Adopt**                     | qBittorrent 5 exposes creator tasks through the official API.                                                        | Capability-gated host-path form with task progress, cancellation/removal, result download, and clear host-filesystem wording.                   |
| Live transfer graphs                                                    | **Adopt**                     | A graph makes current transfer behavior legible at a glance.                                                         | Small Canvas or batched SVG graph backed only by a bounded browser-collected sample buffer.                                                     |
| Configurable torrent fields/columns                                     | **Adopt**                     | Different operators prioritize different metrics.                                                                    | One strong virtualized desktop table with hideable, reorderable, resizable, persisted columns.                                                  |
| Density preferences                                                     | **Adopt**                     | A large library and a touch screen need different spacing without changing the information model.                    | A small set of deliberate desktop and mobile density levels with touch-target constraints.                                                      |
| Mocked development data                                                 | **Adopt**                     | Realistic mocks accelerate deterministic development and edge-case testing.                                          | MSW-backed qBittorrent response fixtures, including large libraries, partial add results, failures, and capability variants.                    |
| Card-first desktop torrent management                                   | **Reject**                    | Cards consume vertical space and make cross-row comparison harder in large libraries.                                | The desktop anchor is a dense, virtualized table; cards are not a competing desktop display mode.                                               |
| Oversized mobile torrent cards                                          | **Reject**                    | Tall cards sharply reduce scan rate and make selection-heavy work tedious.                                           | Compact semantic rows with name, progress, essential transfer metrics, state, and a discoverable overflow action.                               |
| A label above every torrent value                                       | **Reject**                    | Repeated labels create visual noise and dominate the actual values.                                                  | Stable typographic positions, concise symbols where unambiguous, accessible names, and expanded detail on demand.                               |
| Excessive colored chips                                                 | **Reject**                    | Many saturated pills compete for attention and make ordinary metadata look urgent.                                   | Neutral metadata text; restrained badges only where they materially improve recognition.                                                        |
| Strong status color across an entire row                                | **Reject**                    | Large color fields reduce readability and can make the table feel alarm-heavy.                                       | Status uses a small indicator, progress treatment, concise text, and warning/error icon; meaning never relies on color alone.                   |
| Large statistics cards in the primary sidebar                           | **Reinterpret**               | Current speed and health belong near the torrent list, but large cards displace navigation and filters.              | Compact speed values, a small live graph, and a short session summary at the top of a resizable sidebar.                                        |
| Mobile navigation drawer covering most of the screen                    | **Reject**                    | A frequent navigation action should not obscure the working context or require repeated open/close cycles.           | Bottom navigation for Torrents, Search, RSS, and More; full-screen sheets are reserved for complex tasks.                                       |
| Mobile as compressed desktop                                            | **Reject**                    | Desktop tables, toolbars, and dialogs do not become usable merely by shrinking them.                                 | Dedicated mobile list and detail routes, touch-safe contextual actions, bottom sheets, and no page-level horizontal scrolling.                  |
| Several redundant display modes                                         | **Reject**                    | Multiple weak modes increase settings and testing cost while fragmenting learned behavior.                           | One optimized composition per viewport class, with density and column controls instead of parallel card/list/table products.                    |
| Icon-only primary toolbar                                               | **Reinterpret**               | Familiar icons can save space, but ambiguous operations need visible language.                                       | Labels accompany ambiguous actions; every icon button has an accessible name and tooltip where useful.                                          |
| Optional backend for UI preference storage                              | **Reject**                    | A production sidecar adds deployment, security, and maintenance cost for interface-only state.                       | Prefer qBittorrent `clientdata/load` and `clientdata/store` on API 2.13.1+; use versioned, namespaced local storage otherwise.                  |
| Full visual component framework with a recognizable Material appearance | **Reject**                    | Framework defaults can overpower product identity and add weight for controls that need dense, specialized behavior. | Tailwind, CSS design tokens, and accessible unstyled/headless primitives with an original visual system.                                        |
| **Guardrail:** one monolithic API provider                              | **Reject**                    | It couples unrelated capabilities and makes version-specific behavior difficult to isolate and test.                 | Shared typed HTTP core plus `auth`, `app`, `sync`, `transfer`, `torrents`, `search`, `rss`, `torrentCreator`, `logs`, and `clientData` modules. |
| **Guardrail:** loose `any`-based API models                             | **Reject**                    | qBittorrent responses vary by API version; unchecked shapes hide incompatibilities until runtime.                    | Strict TypeScript raw models, normalized domain models, targeted runtime validation, and explicit capability checks.                            |
| **Guardrail:** deriving API contracts from a competitor                 | **Reject**                    | A competitor may contain compatibility workarounds or target a different API generation.                             | Verify route, method, encoding, parameters, response, status codes, and minimum version against qBittorrent 5.2.3 source and its changelog.     |

## Resulting product position

The project retains the competitor's strongest product-level lesson—an alternate WebUI can offer broad qBittorrent coverage and credible mobile access—while choosing a materially different interaction model. The primary desktop surface is an information-dense torrent table with progressive disclosure. Mobile is a compact, route-based manager rather than a tall card feed plus drawer. The implementation remains a standalone qBittorrent Alternative WebUI with no required backend or database.
